# VPN на AmneziaWG (ООО «Тридит»)

VPN-сервер `pm-vpn.3dit.ru` (UDP 51820) и портал выдачи клиентских конфигов. Клиенты направляют через VPN
**только** подсети из `allowed-ips.txt` (заблокированные сервисы), остальной трафик идёт напрямую.

Сотрудники получают конфиги сами: один общий QR открывает портал `https://pm-vpn.3dit.ru/`. Вход: код доступа
**своей организации** (5 цифр) + телефон + фамилия и имя (без SMS) + капча. Первый свободный конфиг выдаётся по кнопке,
число устройств на человека не ограничено (администратор может задать лимит вручную), скачать свой конфиг можно повторно (например, для переустановки). Ссылки на приложения
для iPhone, Android, Windows, macOS и Linux есть на той же странице.

Два уровня администраторов:

| Кто | Адрес | Что может |
|---|---|---|
| Общий администратор | `/super` | создавать, переименовывать и удалять организации, менять код доступа организации, включать и отключать доступ, видеть число выданных ключей и **суммарный трафик по организации**, увеличивать и уменьшать лимит ключей (кнопки ±10 или точное число), освобождать любые конфиги, выгружать всё для переезда (резервная копия) |
| Администратор организации | `/org` | видеть людей своей организации и их конфиги (1–3) с **суммарным трафиком по каждому человеку**, освобождать конфиги, выгружать CSV; видит код доступа своей организации; чужие организации не видит |

## Что где лежит

| Файл | Назначение |
|---|---|
| `allowed-ips.txt` | Подсети, которые уходят через VPN (попадают в `AllowedIPs` клиентов) |
| `scripts/generate.py` | Ключи, серверный `awg0.conf`, клиентские `.conf` (пул из 500 конфигов, подсеть 10.8.0.0/23) |
| `scripts/install-server.sh` | Установка AmneziaWG на Ubuntu и запуск `awg0` |
| `portal/portal.py` | Портал (Flask + SQLite): организации, выдача конфигов, капча, два уровня администраторов |
| `portal/backup.py` | Шифрованная резервная копия состояния портала (для переезда) |
| `scripts/sync-peers.py` | Служба от root: применяет список разрешённых пиров к AmneziaWG (отключение организации и освобождение ключа действуют на VPN) |
| `scripts/collect-traffic.py` | Служба от root (раз в минуту): копит трафик по пирам в `/var/lib/vpn-portal/traffic.json` |
| `scripts/restore-backup.py` | Восстановление резервной копии на новом сервере |
| `portal/test_portal.py` | Автотесты портала: `python3 portal/test_portal.py` |
| `scripts/setup-web.sh` | Установка портала, nginx, сертификата Let's Encrypt и fail2ban |
| `scripts/fetch-apps.sh` | Официальные релизы Amnezia с проверкой SHA256 для раздачи с сервера (`/apps/`) |
| `scripts/make_qr.py` | Единый QR на портал (`out/qr-portal.png`) |
| `deploy/` | Конфиги nginx, сервисов systemd (портал, vpn-peer-sync) и fail2ban |
| `clients.csv` | Список конфигов: имя, IP в туннеле, публичный ключ (секретов нет) |
| `secrets.tar.age` | **Зашифрованные** ключи сервера и клиентов и параметры обфускации |

Репозиторий публичный, поэтому приватные ключи хранятся только в `secrets.tar.age` (шифрование
[age](https://github.com/FiloSottile/age)). Ключ расшифровки `age-key.txt` в git не попадает: храните его в менеджере
паролей. Без него подключения не восстановить.

## Восстановление конфигов из репозитория

```bash
git clone https://github.com/3dit-lab/vpn && cd vpn
age -d -i /путь/к/age-key.txt secrets.tar.age | tar xz      # создаст secrets/state.json
pip install cryptography "qrcode[pil]"
python3 scripts/generate.py --endpoint pm-vpn.3dit.ru --port 51820 --clients 500 --subnet 10.8.0.0/23
python3 scripts/make_qr.py  --url https://pm-vpn.3dit.ru/
# результат в out/: server/awg0.conf, clients/*.conf, qr-portal.png
```

Ключи и параметры обфускации берутся из `secrets/state.json` и не меняются, поэтому клиентские конфиги остаются прежними.

## Развёртывание на сервере (Ubuntu)

На сервер нужно скопировать репозиторий (`git clone`) и из архива каталоги `server/` и `clients/`.

1. VPN: `sudo ./scripts/install-server.sh server/awg0.conf`. Порт **51820/udp** должен быть доступен снаружи.
2. Портал: `sudo DOMAIN=pm-vpn.3dit.ru EMAIL=<почта> IGNOREIP="<ваш офисный IP>" ./scripts/setup-web.sh clients`.
   Нужны открытые порты **80 и 443 (TCP)** и A-запись домена на сервер. Скрипт ставит пакеты (nginx, certbot, Flask,
   gunicorn, fail2ban), запускает портал (`vpn-portal`) и службу синхронизации пиров (`vpn-peer-sync`), получает
   сертификат, включает fail2ban, скачивает приложения. **В конце он выводит пароль общего администратора: запишите его**
   (хранится в `/etc/vpn-portal.env`).
   Порядок важен: сначала VPN (шаг 1), потом портал. **Пока в портале нет выданных конфигов, в `awg0.conf` остаются
   только разрешённые пиры, то есть никого:** сервис синхронизации оставляет в нём лишь тех, кому конфиг выдан через портал.
   Если устройства уже подключены по конфигам, розданным вне портала, сначала выдайте их через портал или не запускайте
   синхронизацию (`systemctl disable --now vpn-peer-sync.path vpn-peer-sync.timer`).
3. Организации: войдите на `https://pm-vpn.3dit.ru/super`, создайте организацию (название, логин, код доступа
   или случайный, лимит ключей). Пароль администратора организации показывается один раз: передайте его вместе с логином.
4. Проверка: `awg show awg0` (у подключённых клиентов будет свежий `latest handshake`), `systemctl status vpn-portal`,
   `fail2ban-client status`, `https://pm-vpn.3dit.ru/`.

Повторный запуск `setup-web.sh` безопасен: база выдачи и пароль сохраняются, новые конфиги добавляются в пул.

## Выдача сотрудникам

Раздайте сотрудникам организации один QR `out/qr-portal.png` и **код доступа их организации**. Дальше сотрудник
действует сам: открывает страницу, вводит код, телефон, фамилию и имя, решает капчу, нажимает «Получить конфиг» и
следует инструкции. Телефон нужен только чтобы найти свои конфиги при повторном входе: проверки по SMS нет, поэтому не
сообщайте код посторонним. Один и тот же телефон в разных организациях считается разными людьми.

### Лимиты, отключение и освобождение

- **Лимит ключей** организации: сколько конфигов могут получить все её сотрудники вместе. Уменьшение лимита ниже уже
  выданного ничего не отзывает, но новые ключи не выдаются. Сумма лимитов может превышать размер пула (500): портал
  выдаёт, пока есть свободные конфиги.
- **Отключение организации** (`/super`): сотрудники не могут войти, а её конфиги **перестают работать на VPN**
  (пиры исключаются из `awg0.conf` службой `vpn-peer-sync` в течение секунд). Включение возвращает всё как было, ключи не меняются.
- **Освобождение конфига** (администратор организации или общий): ключи в конфиге **заменяются**, старое устройство
  перестаёт подключаться, конфиг возвращается в пул и может быть выдан другому.
- **Трафик**: счётчики берутся у AmneziaWG (`awg show awg0 transfer`) и копятся по ключу службой `vpn-traffic`, поэтому
  переживают перезапуск интерфейса и сервера. Показывается сумма «скачано клиентом + отправлено клиентом» по человеку
  (все его устройства) и по организации; при освобождении конфига накопленное остаётся в итоге человека. Это трафик
  внутри туннеля, то есть только запросы к адресам из `allowed-ips.txt`. Точность около минуты. Счётчики входят в резервную копию.
- Журнал действий виден на страницах администраторов.

### Защита

- Капча на входе сотрудников и администратора (картинка генерируется на сервере, внешних сервисов нет).
- Лимиты: 5 неверных кодов за 15 минут с одного IP, 40 в час суммарно (защита от перебора с многих адресов; при
  срабатывании общего лимита вход временно закрыт для всех новых входов, уже вошедших это не затрагивает),
  10 выдач конфигов в час с одного IP.
- nginx: лимит частоты запросов, строже для форм входа.
- fail2ban (`deploy/fail2ban/`): неверная капча, код или пароль (6 за 10 минут) = бан IP на час на TCP 80/443;
  превышение лимита запросов nginx, сканеры и повторные нарушители. VPN (UDP 51820) баны не затрагивают. Свои адреса
  добавьте в `IGNOREIP` при установке, чтобы не забанить себя. Разбан: `fail2ban-client set <jail> unbanip <IP>`.

## Пул конфигов и добавление клиентов

Сейчас 500 конфигов (подсеть 10.8.0.0/23, две /24). Если свободные закончились (админка показывает остаток), увеличьте `--clients` (не более 510 в /23; больше: укажите более широкую `--subnet`, например 10.8.0.0/22)
и запустите `generate.py`: существующие конфиги не меняются, добавляются новые. Затем:

1. обновить серверный конфиг: `install -m 600 out/server/awg0.conf /etc/amnezia/amneziawg/awg0.conf; rm -f /etc/amnezia/amneziawg/awg0.base.conf; systemctl restart awg-quick@awg0; systemctl start vpn-peer-sync` (список пиров тут же сократится до выданных через портал; при смене подсети клиентские конфиги остаются прежними, у них адреса /32);
2. повторить `setup-web.sh clients`: новые файлы попадут в пул, выданные конфиги и база сохранятся;
3. зашифровать обновлённый `secrets/state.json`:

```bash
tar cz secrets/state.json | age -r <публичный ключ из age-key.txt> -o secrets.tar.age
```

## Переезд на другой сервер (без перенастройки клиентов)

Ключ сервера и параметры обфускации хранятся в `secrets.tar.age`, а **актуальное состояние портала** (кто и какой
конфиг получил, организации, лимиты, конфиги с ключами после замен) живёт в `/var/lib/vpn-portal` и **только там**.
Поэтому для переезда нужны обе части:

1. На старом сервере: `https://pm-vpn.3dit.ru/super/backup` → повторно ввести пароль общего администратора, задать
   парольную фразу (не короче 12 символов) → скачать `vpn-backup-….vpnbak`. Файл зашифрован (AES-256-GCM), в нём приватные
   ключи клиентов: храните как секрет. Делайте копию регулярно и после заметных изменений.
2. Новая ВМ (Ubuntu), открыть UDP 51820 и TCP 80/443. Восстановить серверные файлы из репозитория (раздел выше) и
   выполнить шаг 1 развёртывания (`install-server.sh server/awg0.conf`), затем шаг 2 (`setup-web.sh clients`).
3. Восстановить состояние портала: `sudo python3 /opt/vpn-portal/restore-backup.py vpn-backup-….vpnbak`
   (запросит парольную фразу; заменяет организации, людей, выдачи и файлы конфигов). Затем `systemctl start vpn-peer-sync`.
4. Проверить вход в `/super` и `/org`, переключить A-запись `pm-vpn.3dit.ru` на новый сервер. Клиенты подключаются по домену,
   ключи и порт те же, поэтому на устройствах ничего менять не нужно.

Обязательное условие: домен и порт остаются теми, что были при выдаче конфигов.
Резервная копия портала **не содержит** ключ сервера (он в `secrets.tar.age`) и пароль общего администратора
(`/etc/vpn-portal.env`, задаётся заново при установке).

## Изменение списка подсетей

Правка `allowed-ips.txt`, затем `generate.py` и обновление файлов конфигов в пуле (`setup-web.sh clients`). Сервер не
меняется, но клиентам нужно скачать конфиг заново (кнопка «Скачать конфиг» на портале) и импортировать его: список
подсетей вшит в клиентский файл.

## Клиентские приложения

Windows, macOS, Linux и Android: Amnezia VPN. iPhone: Amnezia VPN в российском App Store недоступен, используется
DefaultVPN. Импорт файла и работу конфига в каждом приложении нужно проверить на реальном устройстве до массовой выдачи.
